# 寫程式的四條原則

改善 LLM 寫程式時常見的毛病:亂假設、過度複雜、順手亂重構、沒對準目標。
靈感來源:[andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)(MIT),
以自己的話重寫並貼合本專案。

## 1. 先想清楚再動手(Think Before Coding)
- 動手前先確認需求;有不確定或多種解法時,**先問或先列出取捨**,不要偷偷替使用者做決定。
- 讀相關程式與資料格式再改(本專案資料語意很敏感,見根目錄 `CLAUDE.md` 的資料誠信原則)。

## 2. 優先簡單(Simplicity First)
- 選最直接、最少概念的做法;不引入專案風格外的相依或抽象。
- 新程式要讀起來像周圍既有的程式:命名、註解密度、慣用寫法都對齊。

## 3. 外科手術式改動(Surgical Changes)
- 只改達成目標所需的部分,不順手重構、不重排無關程式、不改無關格式。
- 這是純靜態網站、無建置步驟;改動要能對照 diff 一眼看懂。

## 4. 目標導向(Goal-Driven Execution)
- 動手前先講清楚「怎樣算完成」與如何驗證;完成後據此確認。
- 涉及網站互動時,用 Playwright MCP 實際開瀏覽器驗證(見根目錄 `CLAUDE.md`)。

## 收尾
- 誠實回報:測試有跑就講結果,有跳過就說跳過,別誇大。
- 不確定就停下來問,別用假設硬幹。
